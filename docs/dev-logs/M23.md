## Changes

### 0053 归一化互斥

- `normalizeValue`（shared/scenario.ts 导出）：NFKC 全半角折叠 + 空白折叠 + lowercase，只做格式归一不做语义改写——「北京」与「北京市」归一化后仍不同。
- `deriveConflicts` 互斥判定从裸文本不等改为归一化取值差：格式差异（大小写/空白/全半角）不再假冲突。
- 三份既有归一化拷贝收口（applyAction 的 normalizeMemoryCandidateKey、dream 的 existing 键、memoryDream 的 normalizeMemoryText）统一走 normalizeValue。

### 0054 禁写双路（schema v6）

- memories 加三列 `banned_object_id / banned_predicate / banned_value`：migrateToV6（addColumn×3 幂等）+ SCHEMA_VERSION=6 + SCHEMA_SQL 同步；旧库与旧备份经既有迁移路径自动兼容。
- 纠正已晋升主张时，禁写记忆在原文本外补结构化三字段（对象、谓词槽、归一化取值）。
- `bannedHit` 双路判定（brief.ts）：结构化路（同对象同槽同归一化取值）**或**原句路（现行子串逻辑原样保留）任一命中即拦——原句路绝不删，否则升级即静默解除历史禁写。出站闸与提议生成闸共用。
- eval：`correctionRecurrence` 升级双路重放——纠正后向同来源重放一条仅格式不同的主张（大小写上移+尾随空白：归一化等值、子串必漏，专测结构化路），断言出站闸不放行 + 晋升提议被拒队列不增；`QUALITY_POLICY_VERSIONS.outbound` 升 `ledger-outbound-v3`（回落未认证是设计内）。

### 整理三提议器（CONTEXT「整理」六件套补齐四件）

- **合并重复**（payload `{kind:'合并重复', keepId, dropIds}`）：成立主张按（对象、受控槽、normalizeValue）分组，组内 ≥2 → 提议保留首条去掉其余；确认删 dropIds、keep 不动，补偿复用批量「整理丢弃」undo（零新 undo kind）。与 deriveConflicts 同一把归一化尺。
- **标过时**（payload `{kind:'标过时', claimId}`，decision 新值 `accept-close`）：validFrom 距今超过 180 天（STALE_AFTER_DAYS，复核提示阈值而非状态）的成立主张提请复核；确认关窗（世界已变），undo 重开、历史不改写（0034）。**判据偏离原计划**：intake 原写「validTo < today」，勘察证明该数据状态在现有写路径下永远造不出（validTo 只在关窗瞬间写入），改为 validFrom 年龄判据——整理的本义就是提示复核。
- **未编目编目**（复用 payload kind '整理'，targetPredicate 改可选）：残留未编目主张每条一卡；PROPOSAL_DECIDE 载荷加可选 `targetPredicate` 人选覆盖，须过 slotIsControlled（0025 防自开槽）；无预选槽的编目卡只在待确认页处理（对话转发链拿不到人选槽）。
- 挂接：EXTRACT_DONE 的 tidy 钩子扩为四提议器，各自带 pending 去重；登记面全数过检（proposalObjectId/proposalTouchesClaims/OPEN_PROPOSAL_CARD 守卫/DELETE_OBJECT 清理/PendingView 渲染）。
- UI：待确认页合并卡（保留/去掉对比 + 一键合并）、复核卡（确认关窗/驳回）、编目卡（槽下拉，未选禁用并入）。
