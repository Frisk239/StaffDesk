# M29 — primary-source marking: the minimal closure (ADR 0062)

## Scope

「主键」词条整块兑现（审计 G1，ADR 0062 三轴拍板）：绑定级角色 + 域名启发建议卡 + 新版过时旧版提议卡 + 转述永不自动过时主键的守护不变量。**派发模式变更**：本刀起 Owner 不再直接派发子代理——启动提示词由用户在另一会话手动派发，实现报告转回 Owner 验收（intake 即 Owner 提示词 + ADR 0062，未另立 intake 文档）。

## Changes

- **绑定级角色（数据层）**：角色存在 (sourceId, objectId) 绑定上（Source.bindingRoles 稀疏 Map——只记显式主键，转述即缺省，不把默认值写成数据）；schema v11 三表重建——source_bindings 加 role（CHECK 主键/转述，默认转述；旧 source 级 sources.role=主键 迁移拷到该来源全部绑定）、claims.close_reason CHECK 放开收「被主键新版取代」、write_queue.kind CHECK 收「设角色」并加 role 列。SET_SOURCE_ROLE reducer 守卫：来源存在/非 virtual/确已绑定/同角色幂等；operations 留痕、补偿写可撤（0034）。脏表只 UPDATE 绑定行 role，不回头全量重写（0056 纪律）。
- **域名启发建议卡**：shouldSuggestPrimary 纯函数——来源域名只认 origin.finalUrl / locator / 本身是 URL 的标题；对象线索只收对象名本身是域名、备注链接、成立主张正文链接；仅主机名全等（去 www），不做名称子串撞二级域（「Go」对 go.dev 会误伤）。建议走 takeover 卡，人确认才写。
- **新版过时旧版提议卡**：冲突派生后双方均出自主键绑定且来源时间可辨（新 v 旧）→ 整理卡「建议：旧版过时？」；人确认才关窗、关闭原因「被主键新版取代」、撤销复用关窗补偿（0034）；不消解冲突（关窗后派生关系才消失，卡面文案写明）。
- **守护不变量**：primaryBackedClaimsNoLongerLive（prev→next 后主键背书的成立主张不得消失/过时）——测试级闸，双向覆盖：自动路径断言空数组、构造违规断言能抓。
- **UI**：来源卡「标为主键 / 改为转述」；建议卡与过时卡走既有 takeover/整理通道；结果卡复用「整理」图标。
