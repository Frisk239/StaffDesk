# 任务状态机四态加停止原因；触顶不是失败；再搜一轮是带上轮语境的新任务

审计建议过五态（含独立「取消」），但取消与手动停止在用户脑中是同一个动作，区分两态要在界面解释一条没人关心的规则；触顶与失败混用「失败」又会污染任务列表语义——触顶是纪律性停止，已成功打开的照写入库（0009），有产出；失败是外部错误（端点、网络、费用），零产出或半途而废。StaffDesk：任务状态 = 待启动 / 进行中 / 已完成 / 已停止，已停止带原因（手动 | 触顶 | 失败）；待启动阶段撤回直接删任务记录，不设取消态；进行中人主动停 = 已停止·手动。失败任务给「重跑」，机制复用「再搜一轮」——再搜一轮与失败重跑都是带上轮语境与失败清单的新任务，不是旧任务续帧；重复抽取由 0024 幂等键兜底，触顶后同样可再搜一轮续上。任务列表挂在对象页顶栏（回放入口扩展），不做全局任务中心：单用户、对象为中心的形态，任务永远从对象开（0016）。
