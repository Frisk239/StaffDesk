# 撤销是追加补偿写，不是删历史、不是快照回滚

晋升回退、关窗重开、禁写解除、批量晋升反悔是同一个模式的五个缺口：账本写动作没有对应的逆动作。逐个设计回退（五套界面、五套留痕口径）会把确认机制越堆越多（0027/0028 已有五套）；快照回滚会抹掉同窗口内其他操作的痕迹，直接违反账本只增不减。事件溯源的标准答案恰好合身：append-only 的账本配补偿动作，撤销本身也是历史的一部分。StaffDesk：账本写动作（晋升、纠正关窗、整理并入/丢弃、绑定、解绑、删除来源、写记忆、批量晋升）一律追加操作日志——动作类型、载荷、时间、关联会话与结果卡；撤销不是删日志，而是追加一条补偿写：晋升的补偿是降回未核、关窗的补偿是重开（须填原因）、禁写的补偿是移除禁写（留痕）。结果卡上的短期撤销与设置页、审计卡里的显式回退入口走同一套补偿原语；补偿本身也是写操作、也进日志，天然支持「纠正你的撤销」。主张抽屉的审计链、整理的留痕、0028 提议的执行记录读的是同一张日志，一表三用。补记：补偿是原子的——覆盖该动作的全部下游效果。纠正（0006 的一动作三效果）的补偿 = 重开旧主张 + 移除那次禁写 + 当时新增的使用者陈述一并关窗（指回补偿记录）；下游效果已被晋升出站的，一键撤销降级为 takeover 确认。不可撤销清单与撤销窗口见 0035。
