# M10 Memory, Research, Radar

状态：已完成主体实现、自测与 owner 复核，等待按 M9 返修 -> M10 顺序人工合并。

## 用户路径

用户在对象上继续日常工作：对话里透露偏好时，系统只生成可追溯的候选记忆，等待用户在待确认页接受或驳回；用户从对象顶栏发起调研时，系统先体检本机 Agent Reach / mcporter seam，再真实搜索、打开网页，成功打开的材料才写成调研来源并进入抽取；用户可为对象创建每日雷达，手动或启动补跑时走同一条调研路径，回放中能看见搜索、打开、失败 URL、触顶、迟跑和未跑记录。

## Must

- 候选记忆只从使用者消息原文抽取；闲聊与明确「记下来：...」不进候选。
- 候选记忆 payload 必须记录对象、会话消息 id 和原文摘录；确认后才并入耐久记忆。
- 独立记忆整理循环只处理候选记忆去重，不碰来源、主张或账本状态。
- Reach adapter 负责统一 doctor / search / open：doctor 用 `agent-reach doctor`，搜索用 `mcporter call exa.web_search_exa`，打开用 Jina Reader；真实依赖不可用时返回安装/降级说明，不造假搜索结果。
- 调研任务审计必须记录体检、搜索、搜索结果或空结果、打开尝试、打开失败、停止原因。
- 只有成功打开且拿到正文的页面才能写入调研 Source；Source 要带 `origin.kind=research`、locator/finalUrl/hash/fetchedAt 和可定位 segment。
- 周期性雷达可创建、可显示下次计划、可补跑；补跑使用同一调研路径，并更新 `lastRunAt` / `nextDueAt`。
- 启动 catch-up 仍只补最新到期雷达；错过周期写 `未跑`，补跑写 `迟跑`。

## Out

- 不做无限后台爬虫、多平台深挖策略、登录态网页绕过或 JS 渲染。
- 不做云同步、向量库、质量回归仪表盘；这些保留到 M11/M12。
- 不把候选记忆自动晋升为耐久记忆。

## 遗留风险

- 当前真实搜索 live 验证受 Exa 网络超时影响，尚未证明这台机器当下能跑完整外网搜索成功链；失败链路已验证为可解释、不造源。
- 记忆抽取现在在每轮非写意图对话后生成候选，比 ADR 里「会话结束」更实时；因为仍是候选且需人工确认，语义上不越权。
- 雷达补跑入口是手动触发和启动 catch-up；常驻期间的精细定时器、通知偏好与摘要横幅仍留到后续桌面可靠性阶段。
