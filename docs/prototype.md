# 产品原型

纯前端、可点、假数据。验证对着一个对象，从丢材料到出简报再到纠正，这条链在界面上是否成立，点下去会不会写出账本不该有的东西。

**不回答：** 真模型、SQLite、Electron 主进程、Agent Reach、抽取循环实现、评测跑分。这些只以状态、徽章或「成品才跑」出现。

账本词条和写纪律以 `CONTEXT.md` 和 `docs/adr/` 为准。**形态以 `prototype/` 正在跑的界面为准**（0026）：工作区 → 对象会话轨 → 主栏对话 → 按需右栏。不要回到档案正中的 CRM 三栏，也不要做成无对象的首页对话。

---

## 放哪、怎么跑

- 代码在 `prototype/`。Vite + React + TypeScript。状态全在内存，刷新即丢。
- `npm run prototype`（仓库根）或 `npm run dev --prefix prototype`。
- 界面中文。浏览器打开后必须能走完下面「主链」。

## 范围

做：

1. 桌面壳：图标轨、工作区（建区时选场景）、对象会话列表、主栏对话、按需右栏
2. Inbox：未绑定来源，绑定须人确认；进料三路——粘贴文本/URL、拖入文件、选择文件（文本文件读正文，PDF/二进制收下标「成品才解析」，0031 语义在成品落地）
3. 档案投影、已绑定来源、简报（右栏标签）；槽表按对象种类分区 + 按工作区场景过滤（0033）
4. 主栏审计卡（删抽屉）
5. 出简报：块结构由工作区场景的简报说明决定（求职面试五块 / 技术选型四块，0033）
6. 纠正（关窗 + 关闭原因 + 禁写）
7. 晋升（按条）；出简报任务结束后批量晋升/保持的 takeover 提议（0016 唯一批量白名单）
8. 撤销（0034/0035）：结果卡一键补偿——晋升回未核、并入回原槽、丢弃恢复、记忆移除、绑定解绑回 Inbox、关窗重开连带禁写与新句；批量晋升的撤销走「批量回退」takeover 确认
9. 待确认：整理提议（含「丢弃未核」，0037）和候选记忆两段；禁写可移除（显式回退）
10. 抽取中 / 未核 / 冲突 / 未知 / 过时 / 未编目 / 禁写 可见；冲突完全派生（0029），只在单值槽上判定；纠正未核主张=直接丢弃、不写禁写（0037）
11. 工作区增删切；对象归档 / 恢复 / 永久删除（级联关窗·对象误建，0032）；「全部对象」找回孤儿（0032）
12. 设置：提供商与模型表单可点；三级自检模拟（连通→能力→认证，0039）出认证徽章与分数卡、编造率红线标红；受控谓词表管理（0025：人加槽）
12. 明 / 暗主题

不做：

- 真检索、真打开 URL、真 PDF 解析
- dream 页面或菜单（内部名，不进界面）
- 调研任务真跑、雷达、回放逐步工具调用
- 设置里真发模型请求（三级自检只做模拟演示）
- 评测仪表盘
- 首启向导、系统托盘、真实金标跑分、密钥库（0038/0039/0040/0041 是成品面，原型不承载）
- 删除来源的 UI（0031 是成品裁决，原型不做；绑定撤销已演示解绑语义）
- 对象别名 / 同一性
- 登录

调研、出简报、任务回放：出简报可走通；调研和回放可点，提示「成品才跑」，不要做假搜索结果灌进账本。

## 形态

对齐 0011 / 0015 / 0026 / 0027。结构以 `prototype/` 为准，不要另做变体。

```
┌──────────────────────────────────────────────────────────────┐
│  图标轨 │ 工作区 · 对象会话          │ 主栏对话 │ 右栏（按需）│
│  Inbox  │ 可收起、可拖宽             │          │ 档案       │
│  待确认 │ 归档 / 恢复 / 永久删除     │          │ 来源       │
│  设置   │                           │          │ 简报       │
└──────────────────────────────────────────────────────────────┘
```

- 打开先进入工作区。左侧是该区的对象会话。没有全局聊天，没有「新对话」当首页。
- Inbox / 待确认 / 设置走图标轨，不是对象页。
- 点开对象：主栏是该对象上的对话；档案、来源、简报按需开右栏，可关、可拖。**右栏只读**，写入在主栏对话流里成交（0027）。
- **档案投影：** 主张按谓词槽分组。右栏冲突上下堆叠 + 冲突标签（窄栏排不下两列）。点一句 → 主栏审计卡里冲突双方真并排。未知格子空着。未核有标记。过时默认不进当前投影，「已关窗」入口仍能打开审计卡。
- **来源：** 标题、进料路径（手给/调研）、主键/转述若已标、绑定对象。未绑定的不出现。
- **对话：** 默认只问、带引用。写入只有明确「这句不对 / 记下来」。卡片分工按 0028：审计卡与结果卡留在对话流（一个只读、一个已发生），纠正与写提议坐在 composer takeover 座位，一次一件。
- **顶栏：** 调研、出简报、任务回放，都挂在当前对象上。出简报只留顶栏。

主张账本不是主表。点投影或引用里的一句打开主栏审计卡，不是抽屉。

### Inbox

顶部可粘贴文本或 URL（URL 只存、标注「成品才抓」，不真解析）。未绑定列表。每条能打开原文。上页必须走绑定：挑至少一个对象，人点确认。可同时挂多个对象。不自动乱绑。绑定成功后该来源从 Inbox 主列消失，右栏来源出现，并触发「抽取中」。

### 待确认

一个页面，两段：

1. **整理提议**（动账本，须人确认）：合并重复、标可能过时、未编目谓词编目
2. **候选记忆**（不自动升）：会话扫出的偏好

每条：接受 / 驳回，也可「在对话里处理」。接受才改内存里的账本或记忆。明确「记下来」立刻写记忆，不走候选。候选记忆是另一条路（会话扫出的偏好）。

## 主链（必须可点通）

种子数据启动后，用户不靠改代码就能做完：

1. 打开 Inbox，看到一份未绑定的官方 JD（手给，文本）。
2. 绑定到组织「栈桥科技」（可同时挂项目「后端实习 2026 秋招」）。须点确认。
3. 打开对象后，右栏「来源」出现该 JD。投影先进入「抽取中」，约 1 秒后出现未核主张（内存直接写入，假装主张抽取循环）。
4. 投影按槽分组。至少有：在招岗位一条、后端主栈两条互斥冲突并排（0029：冲突只在单值槽上派生）、办公地点未知空着、未编目一条（不画冲突、不当定论）。
5. 点开一句，主栏出现审计卡：正文、状态、关闭原因（若有）、冲突双方并排、原文片段、进料路径、是否未核、谓词槽或未编目。
6. 顶栏「出简报」→ 面试简报（求职面试场景五块：组织是谁、在招什么、技术信号、可能问什么、材料缺口；其他场景的块由该场景的简报说明决定）。无出处的句子不准出现。未核必须带标记。冲突摊开双方。未知占位。缺口里写清办公地点未知。出简报任务完成后，若对象仍有未核主张，takeover 出现「全部晋升 / 全部保持」批量卡（0016）。
7. 在审计卡上纠正未核的「评估 Java」主张 → 直接丢弃、不写禁写（0037），派生冲突随之消失；结果卡「撤销」可一键恢复（冲突随之回来）。若纠正的是已晋升主张 → 关窗 + 必填关闭原因（世界已变 / 从未成立）+ 写禁写；旧句仍能从「已关窗」打开。
8. 按条晋升一条未核（takeover 确认）；结果卡「撤销」回到未核；简报里该条不再带未核（若已晋升）。

对话补充：输入普通问题 → 只解释并引用已有主张，不写账本。输入「记下来：简报用条目」→ 立刻一条全局记忆。输入「这句不对」且选中某主张 → 纠正提议坐进 composer takeover（0028），不走闲聊抽取。

## 内存状态（执行会话按此建模，不必做成库）

最小字段，名字跟词汇表走：

- `workspaces[]`：id, name, scenario(求职面试|求学申请|技术选型|尽调研究|自定义)（壳层分组，不是账本实体；场景是预设包，0033）
- `objects[]`：id, kind(人|组织|项目), name, relationIds, workspaceId, archived?
- `sources[]`：id, title, body, path(手给|调研), boundObjectIds[], primary?, workspaceId?
- `slotDefs[]`：name, kind(人|组织|项目), arity(单值|多值), scenarios[]（受控谓词表是数据，0025/0029/0033；空 scenarios = 通用槽）
- `claims[]`：id, objectId, predicate(槽名|未编目), text, status(成立|过时), unverified, validFrom?, validTo?, closeReason?(世界已变|从未成立|来源删除|对象误建), sourceId, span, supersededBy?（0030：未核与状态正交；未知只是页面语义，不是枚举值）
- 冲突：不存表，随时从 claims 派生——同 objectId + 同单值谓词 + 都未关窗 + 有效期重叠 + 取值不同（0029）。关窗后冲突自动消失。
- `briefs[]`：id, objectId, taskId, createdAt, blocks[]（每块句子带 claimIds 和 unverified；块结构由场景的简报说明决定，0033）
- `memories[]`：id, scope(全局|对象|会话), text, kind(偏好|禁写|习惯)
- `inbox`：未绑定 source ids
- `extractJobs[]`：sourceId, status(抽取中|完成)
- `proposals[]`：type(整理|候选记忆), payload 为可辨识联合(整理|丢弃未核|候选记忆), pending
- `tasks[]`：id, objectId, kind(出简报|…), status(待启动|进行中|已完成|已停止), stopReason?(手动|触顶|失败), createdAt（0036 四态）
- `certByProvider{}`：status(未认证|认证中|已认证), recall/faithful/unknown/fabrication（0039 三级自检，模拟跑分；编造率是唯一红线 5%）
- 撤销载荷：可撤销的结果卡带 undo（晋升/批量晋升/整理并入/整理丢弃/记忆/绑定/关窗），UNDO_RESULT 追加补偿写并把原卡撤销入口摘掉（0034）

规则（必须写进 reducer，不要只画在 UI 上）：

- 未绑定来源不投影、不进对象对话默认语境
- 绑定须人确认；确认后才入队抽取
- 闲聊不 `push` claim
- 「记下来」立刻写 memory；纠正立刻关窗 + 禁写
- 未编目不建冲突；冲突只在单值槽上派生，晋升不消解冲突（0029）
- 永久删除对象 = 名下主张级联关窗（对象误建），简报留孤儿快照（0032）
- 简报只读当时能出站的主张；无 claimId 的句子不准生成
- 禁写命中的措辞，简报不得再当单边定论
- 未知格子保持空，禁止用模型常识假句子（原型里就是禁止手写填白）

对话可用脚本回复：按用户问题从当前对象 claims 挑引用。不要现场编新主张。

## 屏幕清单

| 屏 | 有什么 | 没有什么 |
|---|---|---|
| 空工作区 | Inbox 引导丢材料 | 无对象的首页对话 |
| Inbox | 未绑定列表、打开原文、绑定确认 | 自动归类完成态 |
| 对象工作面 | 主栏对话 + 顶栏 + 按需右栏（只读）、场景标签 | 主张主表、compiled truth 简介、抽屉 |
| 审计卡 | 审计字段 + 冲突并排 | 置信度分数、浮层抽屉 |
| 简报 | 场景块结构（面试五块 / 选型四块）+ 引用 + 未核 + 缺口 + 历史选择 | 无出处段落 |
| 待确认 | 两段列表，整理提议可送进对话流 | dream、两套审核后台 |
| 对话 | 引用、审计/结果卡、takeover 提议、「记下来」、空态建议问题 | 自动抽主张 |
| 全部对象 | 全部对象（含已归档、含无工作区）、恢复到当前工作区 | — |
| 设置 | 提供商轨、密钥、模型行、受控谓词表（加槽） | 真连模型 |

空态、抽取中、绑定确认、纠正填原因，都要能看见。不要只有成功态。

## 验收

执行者做完后自己点一遍，再交给主人。全过才算原型刀完成：

1. 启动后进入工作区 / Inbox，不是无对象的对话首页
2. 未绑定 JD 不出现在任何对象投影里
3. 不点确认无法绑定
4. 绑定后出现抽取中，随后未核主张上页
5. 档案「后端主栈」出现冲突（单值槽派生，窄栏上下堆叠）；点开后主栏审计卡两条真并排；没有「目前有争议」合成句
6. 办公地点是未知空格，不是「暂无数据请补充」式编造
7. 未编目可见，简报不当单边定论
8. 审计卡能看到原文片段、进料路径、来源标题（Go 那条进料路径是调研）
9. 简报块结构与工作区场景一致（秋招五块；切到选型区是四块）；每句能点回主张
10. 纠正未核主张 → 直接丢弃且记忆区无新增禁写（0037）；纠正已晋升主张 → 关窗 + 禁写，旧句从「已关窗」可打开；两种纠正的结果卡都能一键撤销（丢弃恢复、关窗重开且禁写移除）
11. 闲聊之后主张条数不变
12. 待确认两段都能点；「在对话里处理」把提议送进对话流并在那儿决策
13. 界面中文；无 Graphiti / Mem0 / dream / LightRAG 当功能名
14. 刷新丢失状态（证明没有偷偷做后端）
15. 切到「消息队列选型」工作区：投影槽表换成技术选型预设（活跃度 / 发布节奏 / 许可证 / 性能口径），NordStream「活跃度」出现主键 vs 转述的派生冲突；出简报是四块；设置「谓词表」能加通用槽；「全部对象」能看到全部工作区的对象
16. 撤销全路径（0034）：绑定撤销后来源回 Inbox 且主张撤下、可重新绑定；晋升一键回未核；丢弃一键恢复；批量晋升的撤销走「批量回退」takeover 确认
17. 待确认「丢弃未核」提议接受后主张消失、其派生冲突随之消失，撤销可恢复；禁写行有「移除」（显式回退）
18. 设置三级自检（模拟）：跑完出认证徽章与分数卡，编造率超 5% 标红警告（不阻断）

## 执行时不要做

- 不要把 `reference/` 做成功能
- 不要做成无对象的首页对话
