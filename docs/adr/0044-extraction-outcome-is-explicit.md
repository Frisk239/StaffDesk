# 主张抽取必须返回显式结果；技术失败不伪装成未知或未配置

ADR 0024 规定主张抽取是绑定后的专责循环，并允许“抽不到可核对命题则不写”。但“不写”至少有四种完全不同的原因：原文确实没有主张、没有配置模型、模型输出结构不合格、网络或端点调用失败。若 interface 只返回空数组，调用方无法区分这些情况，结果卡会误导使用者，资格认证也可能把技术失败算成低召回并显示已认证。

StaffDesk：主张抽取 module 的 interface 返回显式结果，至少区分成功（允许零条）、未配置、输出不合格与调用失败。循环内部负责结构化响应解析与校验；IPC 负责把所有终态写回，不得让作业永久停在“抽取中”。页面上的未知仍只表示材料不足，不能承载系统错误。资格认证必须复用同一 interface：技术失败是认证未完成，只有得到合法抽取结果后才计算质量分数。

错误信息只保留可行动的短原因，不记录 API Key、请求头或完整材料正文。测试通过注入模型 completion adapter 穿过同一 interface，不在生产实现里放 mock/stub fallback。
