# 测试数据清单与清理规则

StaffDesk 的测试数据分四类。它们的生命周期和可进入的位置不同；任何一类都不得借“方便演示”
进入使用者的大脑文件。

| 类别             | 位置                                                                                              | 内容边界                                                                                   | 保留与清理                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 内置虚构金标     | `app/src/main/eval/goldPacks.ts`                                                                  | 虚构对象、来源事实、期望主张/出处/检索排名/冲突/纠正/未知与负例。来源正文不放测试控制指令  | 随代码版本保留；变更必须提升评测集或策略版本并复跑 `npm run eval`                                                 |
| 自动测试 fixture | `app/tests/` 及测试进程创建的 `staffdesk-*` 临时目录                                              | 只为单元、集成、E2E 构造；不得含真实 API Key                                               | 测试 finally/afterEach 删除。失败残留只允许位于系统临时目录，可直接删除，不迁入 `app/data`                        |
| 真实端点现场试跑 | 设置页“资格认证”；记录位于 Electron `userData/quality-qualification.json`                         | 真实端点与模型跑内置虚构金标。记录只含配置指纹、安全端点身份、模型、版本、时间、阶段与指标 | 最多保留近期 20 个指纹历史；配置变化不删除旧史，但旧史不能认证新配置。金标正文、请求、响应和 Key 不持久化         |
| 使用者测试数据   | 使用者主动选择的大脑文件；开发态默认 `app/data/brain.db`，发布态位于 Electron `userData/brain.db` | 只能是使用者在真实测试过程中亲自导入或操作产生的数据                                       | 不由测试脚本或资格认证清理。需要删除时必须由使用者按产品内删除/关窗规则操作；仓库已忽略 `app/data/*.db`，不得提交 |

质量回归每个金标包都创建独立 `staffdesk-eval-*` 临时目录，成功或失败均先关闭 SQLite，再在
`finally` 中递归删除。命令行与设置页共用这条 runner；设置页仅替换为当前 BYOK completion adapter。
单测禁止真实外网，URL/PDF 的获取只在注入的边界 adapter 上验证。

排查失败时可以保留阶段短原因、包 ID 和数值指标；禁止把 API Key、Authorization 请求头、金标正文、
模型完整请求/响应或任何使用者来源正文复制进日志、资格记录和提交。
