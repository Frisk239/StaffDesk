# 场景是工作区级预设包：槽表预设 + 简报说明 + 建对象引导；不是第四种对象

产品被面试场景越锚越窄：简报说明只有面试五块，槽表偏组织（人只有一个槽），种子全是秋招。但底座本来就通用——「项目」的定义是「你盯的这一次事」，求学、选型、尽调与面试完全同构（学校=组织、导师=人、申请方向=项目）。为每个场景写分支代码会扩架构，把场景做成数据则只扩配置。StaffDesk：场景是一组同构办事意图的预设包，三件套——按对象种类的谓词槽表预设、简报说明模板、建对象引导。挂工作区级：建工作区时选定，区内对象继承；不挂对象级，避免同区内槽表打架。内置四个场景加自定义兜底：求职面试（默认）、求学申请、技术选型、尽调研究。谓词表仍全局受控一张（0025 不变），每条槽带可选的场景适用标记，对象页投影按当前工作区场景过滤、通用槽恒显示——换工作区时主张不丢，只是投影过滤变；槽表按对象种类分区，「人」的槽在各场景预设里补齐（任职于、教育背景、公开观点、参与项目等）。简报说明由场景决定（0016 的面试五块降为内置预设之一）。场景不是第四种对象、不是任务种类、不产生新账本结构。金标包按场景选材（0010）：内置面试、求学、选型三包虚构金标，资格认证默认跑当前工作区场景对应的包。场景预设随应用版本更新，自定义场景存本地。补记（0041）：预设包从三件套扩为四件套——槽表预设、简报说明、建对象引导之外加默认说明书（按场景预置、人维护）；场景模板成为可管理对象（内置只读、自定义可建改删、四件套齐全），AI 可提议起草模板，草稿走 takeover 提议，模板内新槽逐个按 0025 提议加槽。
