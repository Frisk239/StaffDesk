# Electron 实机用户路径走查与缺陷验收（2026-09-03）

本文是交给后续开发会话的修复输入。结论来自真实 Electron 开发窗口中的正常用户操作，
不是浏览器壳模拟，也没有使用 Playwright CLI。本文只记录现象、代码线索和验收条件；本轮未修改产品实现。

## 1. 测试环境与范围

- 平台：Windows，时区 Asia/Shanghai（UTC+8）。
- 启动方式：仓库根目录执行 `npm run dev`。
- 应用形态：Electron 主窗口，preload 与本机大脑文件均为真实运行链路。
- 工作区：`秋招`，场景为「求职面试」。
- 测试对象：`走查样例-0903`，类型为「组织」，备注为「仅用于交互走查」。
- 测试来源：`走查样例-0903 是一家测试组织，办公地点在杭州，后端主栈为 Go，使用 React。`
- 覆盖路径：建对象、文本进料、绑定、抽取、审计、晋升、问答、待确认、出简报、
  批量保持、任务列表、任务回放、对象档案、关系入口、工作区表单、模型设置与诊断页。
- 未执行：删除来源、删除对象、恢复大脑、修改 API Key、运行外部调研、启动周期性雷达。

测试产生的数据仍保留在本机开发 profile 中，便于开发会话复查。清理这些数据属于删除操作，不在本轮执行。

## 3. 缺陷用例

### UX-001：整理提议立即建议丢弃新主张，且晋升后提议不失效

**级别：P1**  
**关联约束：ADR 0037、账本纪律**

复现：

1. 给对象绑定一条新文本来源。
2. 等待抽取完成，得到 4 条未核主张。
3. 晋升其中“办公地点”主张。
4. 打开「待确认」。

实际结果：

- 刚生成的 4 条主张立即被称为“滞留未核”，系统建议全部丢弃。
- 提议明细仍包含已经晋升为成立的“办公地点”主张。
- 如果用户直接接受，会把不应再属于该提议范围的主张纳入删除动作。

预期结果：

- “滞留”必须有明确且可测试的时间或事件阈值，刚抽取的主张不能立即进入滞留清理。
- 主张晋升、纠正、关窗或被删除后，引用它的挂起提议必须失效、刷新或在接受时重新校验 live state。
- 接受批量丢弃时只能作用于当前仍为成立且未核的主张，并向用户展示最终实际作用范围。

代码线索：

- `app/src/main/loops/tidy.ts:17-31`：`proposeDropUnverified` 选择全部成立且未核主张，没有滞留阈值。
- `app/src/main/brain/claimActions.ts:304-325`：`PROMOTE_CLAIM` 只翻转 `unverified`，不刷新引用该主张的提议。
- `app/src/main/brain/proposalActions.ts:160-180`：接受丢弃提议时应再次校验 live claims。

验收条件：

- 增加“新抽取主张不会立即产生滞留丢弃提议”的纯函数测试。
- 增加“提议产生后晋升其中一条，接受提议不会删除已晋升主张”的 reducer 测试。
- 界面不再同时展示“成立主张”和包含它的“丢弃未核”挂起提议。

### UX-002：聊天正文泄漏内部引用标记

**级别：P1**  
**关联约束：界面不得暴露内部机制名或内部协议**

复现：

1. 对已存在主张的对象提问，例如“这个组织的办公地点在哪里？”。
2. 等待模型回答。

实际结果：

```text
走查样例-0903 的办公地点在杭州。[ref:cl-x-...]
```

正文下方同时还有一枚正常的可点击引用卡，形成重复展示。

预期结果：

- `[ref:...]` 只作为模型与程序间的内部协议。
- 用户正文应剥离合法引用标记，引用只通过引用卡或产品化脚注展示。
- 非法或不在白名单内的引用也不能原样泄漏。

代码线索：`app/src/main/loops/session.ts:107-113` 已抽取 `claimRefs`，但 `replyText` 仍直接使用
`result.content`。

验收条件：

- 合法、非法、重复和紧邻标点的 `[ref:...]` 均有单测。
- 最终正文不含 `[ref:`，引用卡仍能正确打开审计详情。

### UX-003：简报中的未编目主张被重复降级包装

**级别：P1**  
**关联约束：ADR 0037、简报出站闸**

复现：

1. 保留一条谓词为「未编目」的主张。
2. 点击「出简报」。
3. 查看右侧简报的「材料缺口」。

实际结果：

```text
材料提到：材料提到：材料提到：走查样例-0903 是一家测试组织
（未编目，不作定论）（未编目，不作定论）（未编目，不作定论）
```

预期结果：只包装一次：

```text
材料提到：走查样例-0903 是一家测试组织（未编目，不作定论）
```

代码线索：

- `app/src/shared/brief.ts:174-185` 已生成降级文案。
- `app/src/main/brain/briefOut.ts:41-63` 在出站净化时再次包装。
- 修复时应让降级操作幂等，不能只针对当前字符串做脆弱特判。

验收条件：

- `buildBrief`、出站净化一次和重复净化三种路径输出一致。
- Markdown 复制与 `.md` 导出的文本也只能出现一次包装。

### UX-004：已完成任务的回放没有步骤

**级别：P1**  
**关联约束：ADR 0018、ADR 0049**

复现：

1. 点击「出简报」并等待完成。
2. 打开「任务」，找到状态为「已完成」的简报任务。
3. 点击「打开回放」。

实际结果：页面显示“已完成 / 出简报 / 还没有步骤”。

预期结果：至少能看到任务开始、读取账本/组装简报、出站校验、任务完成等可审计阶段；如果某类任务
设计上不产生步骤，任务列表不应承诺“回看过程”，且不应提供一个内容为空的回放入口。

验收条件：

- 完成的简报任务至少有一条审计步骤，步骤顺序稳定。
- 失败或中止任务也能在回放中看到失败阶段与安全错误摘要。
- 增加任务生成到 ReplayView 的集成测试。

### UX-005：抽取完成后仍显示“抽取中”

**级别：P2**

复现：绑定来源并等待抽取完成。

实际结果：同一会话中同时存在：

- `已绑定 1 个对象 · 抽取中`
- `抽出 4 条主张，全部未核`
- 来源页 `已抽取 4 条`

第一张结果卡永久保持“抽取中”，视觉上像仍有后台任务。

代码线索：`app/src/main/brain/sourceActions.ts:100-105` 把瞬时状态写成不可变的历史结果卡。

预期及验收：历史卡应表达事件而非当前状态，例如“已绑定 1 个对象，已开始抽取”；当前运行状态应由
`extractJobs` 单独投影。抽取完成后页面不得再有无上下文的“抽取中”。

### UX-006：UTC 时间被当成本地时间展示

**级别：P2**

复现：在 Asia/Shanghai 时区生成简报并记录系统时间。

实际结果：本地约 14:23 创建，任务与简报显示 `2026-09-03 06:23`，相差 8 小时。

代码线索：

- `app/src/main/brain/objectChatActions.ts:65` 使用 `new Date().toISOString()` 后直接截取。
- `app/src/shared/brief.ts:210` 有相同写法。
- `app/src/renderer/src/components/TasksView.tsx:40` 却把该字段声明为“本地戳”。

预期及验收：明确持久层采用 UTC 还是带时区时间；展示层统一转换为用户本地时间。至少覆盖 UTC、UTC+8
及跨日边界测试，排序仍按真实时间而非格式化字符串语义工作。

### UX-007：右侧来源面板包含写操作

**级别：P2**  
**关联约束：ADR 0027**

实际结果：右栏「来源」详情直接提供“标为主键”“解绑当前对象”“删除来源”“重试”等写操作。

预期结果：按 `docs/adr/0027-writes-happen-in-chat-panel-is-read-only.md`，右栏用于查看档案、来源和简报；
产生账本变化的操作应进入主栏并通过对应确认流程成交。

验收条件：

- 先判断现实现是否构成新架构决策；若要改变 0027，必须先写新 ADR，不能口头覆盖旧决策。
- 若维持 0027，右栏入口只能打开主栏提议/确认卡，不能直接落写。

### UX-008：新建工作区表单在窄侧栏重叠

**级别：P2**

复现：展开工作区菜单，点击「新建工作区」。

实际结果：五个场景按钮挤成多行，覆盖场景说明；说明文字与工作区名称输入区贴叠，点击目标不清晰。

预期及验收：在默认窗口宽度及侧栏展开/收起状态下，按钮、说明、输入框和操作按钮均不重叠；场景多于
一行时布局仍稳定。建议补组件级尺寸测试或视觉回归用例。

### UX-009：批量确认卡数量文案自相矛盾

**级别：P2**

实际结果：同一卡片顶部显示“本对象还有 0 条”，正文显示“本任务未核 3 条”。

代码线索：`app/src/renderer/src/components/Takeover.tsx:22-25` 的 `restHere` 统计的是当前对象剩余的
`writeQueue` 项数；一个“批量晋升”项内部可包含多条主张。

预期及验收：明确区分“还有 0 个待确认操作”和“本操作包含 3 条主张”；禁止两个不同统计口径都使用
无修饰的“条”。单条、批量、其他对象有队列三种情况均需组件测试。

### UX-010：对象侧栏数字没有语义标签

**级别：P3**

实际结果：对象副标题从“组织 · 1”递增到“组织 · 10”。代码表明该数字是
`chatByObject[o.id]?.length`（`app/src/renderer/src/components/Chrome.tsx:309-327`），其中包含用户消息、
回答和系统结果卡，并非未读数或主张数。

预期及验收：删除低价值数字，或明确显示为“10 条会话记录”并提供一致的计数定义。不能让它看起来像未读数。

### UX-011：主张引用 chip 横向裁切

**级别：P3**

实际结果：抽取结果和批量保持结果中的多枚主张 chip 在主栏右缘被切断，没有换行、滚动条或展开提示。

预期及验收：默认窗口宽度、右栏打开和关闭时都能访问全部引用；可采用换行、明确横向滚动或“其余 N 条”
展开，不得静默裁掉可操作项。

### UX-012：成功状态下使用“重试”

**级别：P3**

实际结果：来源已显示“已抽取 4 条”，旁边操作仍叫“重试”。

预期及验收：失败状态使用“重试”，成功状态使用“重新抽取”或不显示该入口；重新抽取前明确说明幂等和
已有主张处理规则。

### UX-013：审计卡暴露内部主张 ID

**级别：P3**

实际结果：审计卡底部直接显示 `cl-x-2acf...`。

预期及验收：普通用户界面默认隐藏内部 ID；如诊断确实需要，应放入可复制的“技术详情”折叠区，且不与
来源、谓词等主要信息竞争视觉层级。

### UX-014：创建对象后疑似点击穿透到归档

**级别：待确认，确认后按 P1 处理**

单次观察：

1. 打开「新建对象」，输入 `走查样例-0903`。
2. 点击「创建」。
3. 对象短暂出现后立即进入“已归档 1”；在「全部对象」中恢复成功。

线索：新建表单的“创建”按钮位于侧栏右侧；表单关闭并插入对象行后，同一位置接近新对象行的“归档”按钮。
本次由 Computer Use 触发，尚不能排除自动化输入的按下/抬起时序差异。

二次复现要求：

- 用物理鼠标慢点和快点各重复至少 5 次。
- 再用键盘提交重复 5 次作为对照。
- 记录是否只有指针点击触发，以及 `pointerdown`、`click`、form submit、归档 dispatch 的事件顺序。
- 未坐实前不要把它写成确定的 reducer 错误；一旦坐实，应避免新布局把危险按钮放在提交按钮原位置。

## 4. 正向基线（修复时不得回归）

以下行为本轮符合领域约束：

1. 查询未核的“后端主栈”时，回答明确带“（该条未核）”。
2. 已晋升的“办公地点”在简报中可以作为成立主张出站。
3. 未核技术主张在简报中均带“未核”。
4. 缺少“在招什么”材料时显示“未知”，没有编造负事实。
5. 点击一次「出简报」只生成一条任务，本轮没有复现重复简报任务。
6. 选择“全部保持”后，三条主张仍保持未核，没有发生批量晋升。
7. 添加关系流程默认不选对象，确认按钮禁用，取消不会写入关系。

## 5. 开发与回归要求

- 涉及新设计裁决时先按仓库规则新增 ADR（从 0064 顺延），尤其是右栏写操作和“滞留”定义。
- 账本规则修复优先落纯函数测试；不要只用组件文案遮住 live state 错误。
- 至少新增针对 UX-001、UX-002、UX-003、UX-004、UX-006、UX-009 的自动化测试。
- 组件测试禁止快照，断言用户可见状态与交互结果。
- 交付前执行：`npm run lint`、`npm run typecheck`、`npm run test`、`npm run eval`、`npm run e2e`。
- 修复后重新用真实 Electron 窗口走同一条路径，不能只以 reducer 单测或浏览器页面作为验收。
- 新批次完成后在 `docs/dev-logs/` 写对应里程碑验收记录，并逐项回填本文件中的 ID。

可恢复流程处理，不要直接删除整个 `brain.db`。
