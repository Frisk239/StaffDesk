# M9 Real Ingestion

状态：已完成实现与自测，等待人工合并。

## 用户路径

用户在 Inbox 或首启向导放入一份真实材料：粘贴文本、URL、TXT 或 PDF。主进程负责获取和解析；只有拿到非空、可定位的正文后才生成 Source。用户绑定 Source 到对象后，抽取循环覆盖完整正文并写入未核主张。失败的 URL/文件停留在导入任务里，可重试，但不会进入业务来源或主张账本。

## Must

- Inbox 与向导共用 ingestion IPC；renderer 只发起文本、URL 或文件选择，不解析正文。
- URL 只支持 http/https；成功获取真实正文后才创建 Source，失败不得把 URL 字符串当正文。
- TXT/PDF 由主进程读取和解析；空文件、超限、Unsupported MIME、解析失败都只生成失败 job。
- Source 记录 origin、最终 locator、MIME、size、content hash、fetchedAt 与可定位 segments。
- Claim 保持旧字段兼容，同时可记录 source range、segment/page 定位。
- 替换前 8000 字符抽取：按来源 segments 稳定分块，全部 chunk 串行抽取并按绝对位置去重。
- 抽取任一技术失败时本轮不写入新主张；失败状态可重试。
- schema v3 必须包含旧库迁移；v2 数据、旧 claim 和旧 unparsed Source 保留。
- 测试夹具只在 tests/e2e 或临时 brain.db；生产路径不保留 mock/stub fallback。

- E2E 覆盖 Inbox 添加真实文本/URL/文件、绑定对象、抽取完成，以及失败 URL 不进入来源列表。
- Owner 最终运行 typecheck、lint、build、unit tests、Electron E2E，并做一次路径级手验或自动烟测。

## 已交付

- 新增主进程 ingestion 模块，统一处理粘贴文本、URL、文本文件与 PDF；失败只落 IngestJob，不创建 Source。
- URL 获取现在把响应正文读取纳入同一超时边界；文件/PDF 解析也有独立时间盒，超时只生成失败 IngestJob。
- Source 增加 origin、segments、hash、fetchedAt；Claim 增加 sourceStart/sourceEnd/sourceLocator，旧字段保持兼容。
- schema v3 新增 ingest_jobs 表及来源/主张定位字段，旧 unparsed 来源保留但不能再绑定触发抽取。
- Inbox 与 Onboarding 改走 ingestion IPC；向导支持粘贴文本、URL 与 TXT/PDF 文件选择，renderer 不再读取文件正文，不再把 URL/PDF 占位写入业务来源。
- 主张抽取改为按完整 Source 分块串行处理，覆盖 8000 字符之后的正文，并按绝对位置去重。
- 新增 `pdfjs-dist` 作为正式 PDF 文本解析依赖。

## 遗留风险

- URL HTML 正文抽取是轻量清洗，不做 JS 渲染、登录态或正文质量评分；这些属于后续 M10/M11。
- PDF 只处理可提取文字，扫描件/OCR 明确不在本刀范围。
- 抽取分块为全有或全无；未来若成本或长文体验需要，再引入 chunk checkpoint。
