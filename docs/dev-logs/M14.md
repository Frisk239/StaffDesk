# M14 — 大脑备份与恢复边界

## 本批完成

- 新增 ADR 0048：定义 StaffDesk 大脑备份只迁移业务账本，不迁移 API Key、模型端点、当前模型、思考强度、
  资格认证、运行缓存或构建产物。
- 设置页「通用 / 大脑文件」升级为完整用户路径：导出 StaffDesk 大脑备份 zip；恢复备份前给出内联二次确认；
  恢复后展示恢复前安全副本路径。
- 新增 `app/src/main/brainBackup.ts`：生成带 `manifest.json` 的 store-only zip，记录 schemaVersion、大小与
  sha256；恢复前校验 zip 目录、条目、CRC、manifest、SQLite header、integrity 和 StaffDesk 必要表。
- 导出改为通过当前 SQLite 连接的 backup API 生成一致快照，不再直接读可能带 WAL 的 `brain.db`。
- 恢复路径会先导出当前大脑安全副本，再替换目标 `brain.db`，并清理旧 `brain.db-wal` / `brain.db-shm`
  sidecar，避免旧库 WAL 叠到新库上。
- `window.staffdesk` / preload / IPC 增加 `restoreBrain`，并保持 M13 的 trusted-frame IPC 校验。
- 模型配置类动作不再写入大脑操作日志；旧库打开时会清理历史 `UPSERT_PROVIDER`、`SET_ACTIVE_MODEL` 等残留，
  避免端点 URL 或模型选择随大脑备份迁移。
- 原 `exportZip.ts` 的裸单文件 zip 被替换为带清单的 StaffDesk 备份格式。

## 已知边界

- 本批不做云同步、多大脑切换器、第三方知识库导入、Markdown/PDF 简报导出或旧原型 mock 数据导入。
- 恢复入口只接受 StaffDesk 当前清单格式 zip；若未来需要兼容更早期裸 `brain.db` zip，必须另开迁移策略。
- 恢复时若后台长任务正在写入大脑，当前版本没有任务级暂停队列；后续可把“恢复前暂停/恢复后重启任务”单独做一刀。
