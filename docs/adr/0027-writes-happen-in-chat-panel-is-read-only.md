# 写入在主栏对话里成交，右栏只读；主张抽屉不做成浮层

把晋升、纠正、提议确认都放进右栏或浮在其上的抽屉，主栏对话就退成只读解说器：它复述已入账的主张，不承载任何决策。这不是 0015 / 0021 写错。0015 说的是「写入要经过明确指令」，0021 说的是「对话默认只读，『记下来 / 这句不对』才打写入」——二者都没有说「写入在别处」。实现把写入搬到抽屉和右栏，是执行偏离。0026 拒掉的「CRM 三栏 = 记录浏览器」会从三栏挤成「窄主栏 + 操作右栏」重新回来。

冲突并排归主栏是尺寸账，不是口味。`.conflict-pair` 是 `1fr 1fr`，嵌在 `minmax(320px, 1fr)` 的 `.slot-card` 里；右栏默认 400px（可拖 280–560）。扣掉卡片与冲突框 padding、列间隙，每侧大约 175px。一句「栈桥科技后端主栈是 Go。」要折三四行。冲突摊开双方是这个产品的招牌能力（0003），在右栏宽度里排不下。

业内做法是让待裁决的东西回到对话流：Cursor、Copilot Chat 把改动做成流里待接受的卡片，Claude Code 把工具写入的许可确认留在流里，NotebookLM 点引用是看原文而不是开一个操作台。StaffDesk：任何会改账本或记忆的动作，都以对话流里的卡片发生并确认——审计卡（正文、状态、有效期、进料路径、原文片段、冲突双方并排）、纠正卡（关闭原因必选 + 可选新主张）、结果卡（关窗 / 晋升 / 记忆 / 简报出站）、提议卡。抽屉删除。右栏（档案投影、已绑定来源、简报）只读，不放写入按钮；办事仍在顶栏。Inbox 绑定确认留在 Inbox：那时还没有当前对象。待确认页保留为 backlog，可把提议送进对话流决策，两处走同一条写入路径。

代价：对话流变长且混杂（问答 + 操作记录），长会话里翻历史操作不如列表页方便。缓解：右栏保留只读索引（已关窗、待确认列表），对话流只负责当下这一次决策。

本条细化 0015（对话默认只问、点开一句即审计）与 0026（主栏对话、右栏按需）的落法，不推翻二者：写入仍须明确指令，闲聊仍不抽主张。纠正卡与提议卡后来改坐输入区（composer takeover），模型只能提议不能直接写，见 0028。形态以 `prototype/` 为准。

M38 走查 UX-007：对象页来源面板上的解绑、删除、重试抽取曾直接落写，是执行偏离，不是新裁决。维持本条——设角色已走主栏确认卡；解绑、删除、重试抽取同样改为右栏只留入口、确认卡成交，删除卡须写清影响范围。Inbox 绑定例外不变。
