# 来源可解绑可删除；解绑撤该对象下的主张，删除级联关窗并须列出受影响条数

Inbox 的状态机停在「已绑定」：丢错材料、绑错对象之后没有任何出口，而绑错对象会让主张与来源分家、审计链断掉（refit-3 的一致性检查正是在补这个洞）。只进不出的实体在单用户产品里是最高频的误操作陷阱。StaffDesk：解绑作用于（来源, 对象）一对，该来源在该对象下抽出的主张随之撤销（0024 的幂等键含对象，各对象下的主张本就独立，其他对象下的不动），来源回到 Inbox 未绑定列——语义是「当作没绑过」。删除作用于来源本身，其全部主张级联关窗，须列出受影响主张数并二次确认——语义是材料处置而非判定命题为假，因此新增关闭原因「来源删除」，待遇同「从未成立」：默认不再出站、记录保留以防再写入。历史简报是快照，不因解绑或删除回改。这两条是 0012 的出口补篇；AI 可提议解绑（0028 的 takeover 座位），删除属不可逆操作、不给模型工具。关闭原因枚举随之完整：世界已变、从未成立、来源删除、对象误建（0032）。
