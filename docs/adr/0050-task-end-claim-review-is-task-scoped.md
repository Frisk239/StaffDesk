# 任务末未核决策按任务来源聚合，不按对象全量聚合

0016 已经定下唯一批量白名单：任务结束时，使用者可以对本任务产生的未核主张选择全部晋升或全部保持；没有整站一键全过。M15 之后，调研与雷达运行变成先落账、可停止、可回放，但调研来源完成抽取后还没有把“本任务产生的未核”收束成一次明确决策。

StaffDesk 将调研来源的任务归属写进 `Source.origin.taskId`；历史来源仍可从 `src-res-{taskId}-{index}` 反解。一次调研/再搜一轮任务结束后，等该任务所有调研来源的抽取作业都进入终态，才生成一条 `批量晋升` takeover 提议。提议的 `claimIds` 只来自这些任务来源下仍为 `成立 + 未核` 的主张，不包含同对象的手给来源、旧任务来源或其他对象来源。确认只翻这些主张的 `unverified=false`，不改 `status`，不消解冲突；拒绝表示“全部保持未核”，同样落结果卡但不改主张。

出简报已有的批量卡继续保留，并同样标注 `taskId`。回放页可以提示这条任务还有未核决策待处理，但写账本确认仍坐在对象页 takeover 位置，不复制第二套确认机制。

这样做牺牲了一点实现上的方便：抽取完成时需要检查同任务所有来源是否终态，而不是每个来源抽完立即弹卡。换来的是批量动作的影响面稳定可审计，不会退化成“当前对象所有未核一键通过”。
