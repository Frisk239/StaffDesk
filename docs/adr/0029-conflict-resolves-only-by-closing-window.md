# 冲突只能被关窗消解；晋升不消解冲突；互斥由槽的单值/多值声明判定

0003 定义了冲突的建立，没定义消解；「裁决」「盖过」在术语表里只是名词，晋升冲突一方后简报是定论还是并排，0003 与 0005/0016 两边各说一半。给「裁决」做一个排序或隐藏动作，等于给账本加一个不基于世界事实的选边机制，正是 0003 反对的东西。StaffDesk：冲突的唯一消解路径是任一方关窗（纠正关窗或有效期结束）；晋升（0005/0016）只改变该主张的出站资格，不改变冲突的并排展示，未消解的冲突在简报始终摊开双方、已晋升一侧带出站标记。「未核调研不能盖过手给」在调研侧被晋升后解除其未核限制，但并排保留到手给一方关窗为止；人裁决世界事实的唯一方式是把不成立的一方关掉，没有「判某方胜」的动作。冲突是派生关系不是独立状态：随时可从 claims 按（同对象 + 同受控谓词 + 有效期重叠 + 取值互斥）算出，成品里不维护独立的冲突表，关窗后冲突自动消失（原型 conflicts 列表只是渲染便利）。取值互斥由谓词槽声明判定（0025 的表加一列）：单值槽（如主栈、办公地点）不同取值即互斥，多值槽（如使用技术、在招岗位）并存不互斥、不建冲突；种子里「主栈是 Go」对「也在招 Java」的正确建模是两条都落单值槽「后端主栈」才构成冲突。冲突检出评测只在单值槽上计算。
