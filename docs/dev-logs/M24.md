# M24 — radar resident, proposal finish, 0055, operations index

## Scope

提议收尾（建新对象 0052 收官 + 补关系，吃 M22 的边）+ 雷达常驻（0038「按时跑」半边）+ 0055 候选卡 scope 可改 + operations.action 索引（schema v7，读路径债第一笔）。红线：不动场景模板/谓词表；watchdog 只跑雷达不碰手动任务入口；启动补跑「只补最新一次」语义不变。

## Changes

### 建新对象提议（0052 整理面收官）

- **信号取 draft 层**：`ExtractionOutcome` 加 `unknownObjectNames`——抽取循环收集「objectName 非空且未命中绑定名单」的去重未知名（`draftsToClaims` 的静默归属回落一字未动，主张归属照旧，只新增信号）；经 EXTRACT_DONE action 透传。
- `proposeNewObjects`：每未知名一卡（type '整理'，payload `{kind:'建对象', name, fromObjectId}`）；撞名（含归档）不提；**早退分支（零主张）也挂接**。
- 确认卡：**人选拖种类**（人/组织/项目，PROPOSAL_DECIDE 载荷 `objectKind?` 覆盖，照 targetPredicate 先例）；确认 = 内联复刻对象创建（不 openObject 不抢新对象视图、不自动绑定来源——绑定须人确认，0028）、免 undo（对象可归档回退，operations 留痕）、结果卡落锚对象页提示可手动绑定；未选种类/撞名被拒时提议保持 pending。
- 对象只由人确认建立的裁决（0052）完整保持：抽取与调研路径零自动建对象。

### 补关系提议

- `proposeRelations`：扫锚对象成立主张 text，命中「跨种类、未归档、名字 ≥2 字、双边无边」的既有对象全名（全名出现且不被更长对象名盖住——防「阿里」误配「阿里巴巴」）→ 每对一卡 `{kind:'建关系', objectId, targetId}`。
- 确认 = 复刻对称双侧 append（四重校验防确认间隙归档/删除），免 undo（沿用关系裁决口径）；DELETE_OBJECT 清两端提议。

### 雷达常驻（0038）

- 新建 `tasks/radarWatchdog.ts`：`createRadarWatchdog`（60s tick、brain null 空跳保 restore 窗口安全、多雷达按 due 降序串行、tick 后回调托盘刷新、stop 清 interval）；**抽成可测模块**，5 条专测（到期触发/串行/空跳/stop/错误传播）。
- index.ts：启动补跑后接管 watchdog；`powerMonitor.resume` 即刻补 tick（睡眠唤醒漏周期能立即补，0038）；before-quit stop + 移除监听。启动补跑「latestDueRadar 只补最新一次」的一次性语义未动。
- 托盘菜单可重建：雷达区「下次 …」只读项 +「立即补跑下一班」（无到期时取最近计划雷达提前跑，late=false 不记迟跑，诚实记录纪律不破）；初始与每 tick 刷新。
- `task:createRadar` 透传 `intervalDays`（原硬编码 1）；对象页雷达创建改为 每日 / 每 3 天 / 每周 三档下拉（默认每日）。

### 0055 候选卡 scope 可改（裁决落地）

- PROPOSAL_DECIDE 载荷加 `scope?` 覆盖；reducer 以人选为准回落 payload；候选卡只读 tag 改为下拉（全局/对象/会话），按钮文案动态；选「对象」落 fromObjectId。types 注释更新为已落地。

### operations.action 索引（schema v7）

- `migrateToV7`：`CREATE INDEX IF NOT EXISTS idx_operations_action ON operations(action)`（幂等门次对空旧库都生效）；受益查询 = `listDeletedSourceRecoveries` 每次 dispatch 双 snapshot 的 `WHERE action=?` 全扫降为索引查；旧库重开补齐有专测。
