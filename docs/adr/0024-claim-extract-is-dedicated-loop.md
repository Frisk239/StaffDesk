# 主张抽取是绑定后的专责循环；先入库再抽，不进对话

NotebookLM 是来源处理完才允许对着材料问；Graphiti/Zep 先落下原文，实体和事实在后台抽，同一组串行以免竞态；GBrain 的世界事实走 extract/dream 相位，并跳过自己生成的页，防止抽自己的输出。对话里顺手抽会把闲聊写进账本；把大文档的 LLM 抽取塞进打开动作会把界面卡死（Graphiti 对长文串行抽是反面教材）。StaffDesk：粘贴、打开、调研成功拿到原文先入库；绑定（或调研已绑定对象）后入队主张抽取循环。主会话继续问。抽出的主张默认未核，必须能指回片段，谓词须映射到受控表；映射不上则未编目，不自动判冲突。抽不到可核对命题则不写。按来源串行，幂等键为来源片段、对象、谓词槽（未编目用规范化短语占位），不因循环重跑再追加一行。此循环只写账本，不调眼睛、不写记忆。闲聊和「记下来」仍走对话纪律：前者不抽主张，后者是使用者陈述。整理仍是事后提议，人确认才合并。
