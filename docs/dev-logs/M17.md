# M17 — persistent write queue

## Scope

把 takeover 的待确认写提议从运行时 UI 状态提升为业务账本状态。用户路径：看到一张待确认卡，关闭/重启应用后仍能看到同一张卡，并继续按同一个 `writeId` 确认或拒绝。

## Changes

- 新增 ADR 0051：待确认写提议属于大脑业务上下文，持久化在 `brain.db`；运行中的抽取/导入作业仍是运行时语义。
- schema 升到 v5，新增 `write_queue` 表，并把 `schema.sql` 中滞后的 proposals/tasks 定义同步到当前主 schema。
- `persistLedger` 读写 `writeQueue`；`Brain.snapshot()` 从 SQLite 恢复队列，不再以主进程 UI 内存为真相源。
- 备份验证改为在临时副本上先迁移再校验 REQUIRED_TABLES，避免旧备份因缺少新表被误拒绝。
- 补重启级 brain 单测、schema 迁移测试、旧备份兼容测试，以及 Electron e2e：待确认晋升卡重启后仍显示并可确认。
