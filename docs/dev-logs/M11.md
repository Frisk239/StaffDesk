# M11 — 质量回归与资格认证

## 本批完成

- 新增 ADR 0045：命令行与设置页只使用一套质量回归 runner；资格记录属于产品全局，不进入大脑文件。
- 扩展三套内置虚构金标：显式记录抽取主张与出处、检索 query 与期望排名、冲突、纠正复发、未知和负例；
  来源正文不再夹带“不要写年薪”一类测试控制指令。
- 新增四阶段 runner：获取复用文本进料 seam，抽取复用 `runExtractLoop`，召回复用 FTS 与命中对账，
  出站复用简报、冲突、晋升与纠正规则。每包独立创建 `staffdesk-eval-*` 临时大脑，finally 关闭并清理。
- 报告包含获取 / 抽取 / 召回 / 出站的通过、失败、未运行与安全短原因，并统一计算抽取召回、出处命中、
  Recall@k、Precision@k、MRR、简报忠实、未知遵守、冲突检出、纠正复发和编造率。
- FTS 排名显式使用 `bm25(claims_fts), rowid`，同分结果稳定，避免 MRR 随查询计划漂移。
- 新增配置指纹：规范化 endpoint、模型 ID、思考强度、上下文窗口、最大输出、评测集版本与三段策略版本；
  排除 API Key、供应商 ID 和显示名称。运行开始冻结 target，途中改配置不会把旧结果贴给新配置。
- 资格记录持久化到 Electron `userData/quality-qualification.json`，最多保留 20 个旧指纹；重启和切换大脑
  仍可读取，当前指纹不匹配时立即显示未认证。文件只含安全身份、版本、阶段与指标，不含 Key 或金标正文。
- 设置页顶部新增当前 endpoint + model 资格卡、运行按钮、三级检查结果、四段状态、失败位置与全部指标。
  模型行自检先显式切换到对应 provider + model，再运行；IPC / preload / shared interface 均明确传 modelId。
- 新增 Electron E2E 覆盖设置页模型资格卡的可见布局、全局配置投影和显式运行入口，并用独立
  `--user-data-dir` 隔离测试配置。
- 删除旧 `certByProvider`、`TEST_PROVIDER / SELF_CHECK / CERT_*` 和旧 `cert.ts`，不保留第二套资格状态或 runner。
- 根目录和 `app/` 新增 `npm run eval`，由 Vitest harness 调用同一 runner、金标和指标，确定性 adapter 不访问外网；
  阶段或金标指标回归会令命令返回非零。
- 新增 `docs/test-data-inventory.md`，明确金标、fixture、真实端点现场试跑与使用者测试数据的保留和清理边界。

## 已知边界

- 设置页真实资格认证必须由使用者主动点击，会真实访问其 BYOK endpoint；本批自动测试没有调用真实外网。
- 安全依赖升级需单独开后续阶段：当前 Electron 37 触发 high advisory，直接自动修复会跨大版本到 Electron 44，
  需要配套重跑 native module rebuild、打包和 Electron E2E。
- 当前不做模型排行榜、历史趋势、向量库、真实网页/PDF 金标或模型裁判；旧指纹仅留本机历史，不在界面做趋势展示。
