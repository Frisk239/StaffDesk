# 费用顶按每任务 usage token 计量；硬顶只留可执法的维度

调研档位的硬顶六维缺费用（G4）。计费口径三选一：调用次数近似（实现最简，长上下文与短调用同价，反映不了真实成本）；usage 折金额（贴钱感，但 BYOK 各家价格漂移快，要在设置里维护单价表，货币与倍率不一，维护成本高）；**usage token 数（拍板）**——适配器从 chat.completions 响应解析 usage.prompt_tokens / completion_tokens，按任务累计，硬顶单位是 token。不折金额、不建单价表：token 数是端点回传的稳定事实，金额换算留给用户自己心算，未来真要折价再另议。预算随档位常量（快搜 / 深挖 / 雷达周期各自独立），再搜一轮是新任务、新预算；雷达每个周期独立预算。端点不回传 usage 时不得静默当 0：该次调用退化为调用次数近似（独立小上限）并在任务审计行标注「端点未回传 usage」。触顶行为完全并入既有「硬顶」纪律：已成功打开的照写入库、没拿到的保持未知、原因写任务审计（stopReason=费用触顶）、不编造不作废半成品。usage 数字与密钥无关、不含敏感载荷，可进 brain.db 任务审计，不触发掩码红线。

同刀收口 hops：引擎没有跳链行为（opens 只开搜索命中页，不从正文抽链接再开），hops 声明了却永不执法，属谎言口径——从 Budget 删除，硬顶只留可执法的维度（searches / opens / steps / wallMs / tokens）。要真做跳链是未来的功能刀，届时连声明一起回来。
