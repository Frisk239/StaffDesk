# 对象由人确认建立，整理可提议新对象

抽取与调研材料经常提到尚未建对象的主体（JD 里的一家公司、一篇文章里的作者）。若由系统自动建对象，账本会堆满无人认领的档案，也违反「绑定不自动乱绑」的进料纪律；若要求人事先建全所有对象，检索到的增量主体又没有入口。

StaffDesk 的对象身份只由人确认：抽取永远只把主张写进「来源被绑定到的对象」，系统不在抽取或调研路径上自动创建对象。发现疑似新主体属于整理的提议面：整理可产出「发现疑似新对象」提议，人确认后才建对象，之后才可能挂关系边。关系边因此永远连在两个被人确认过的对象之间，不产生身份歧义。

v1 不做对象别名与改名归并（曾用名、缩写、多来源指同一实体）。等真实使用中出现「同一实体多个档案」的痛点，再立新 ADR 设计别名与合并结构；在那之前不提供对象级合并。

prototype-refit 待拍板 §9 由此裁决。
