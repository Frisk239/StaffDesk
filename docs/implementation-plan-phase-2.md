# StaffDesk Phase 2：从功能齐备走向可信日用

> 状态：执行中（2026-08-30）。M0–M8 已完成；下一阶段为 M9 真实进料。本计划承接 `docs/implementation-plan.md`，不改变既有账本语义。

## 目标

Phase 1 已把 Electron、SQLite、真实模型、抽取、调研、简报、撤销、认证与桌面交付串起来。Phase 2 不先扩展功能面，而是把“丢入真实材料 → 得到可核对主张 → 对话/简报出站”做成可长期使用、失败可解释、可回归的主链。

排序原则：

1. 先修会让用户误判产品状态的问题，再补能力。
2. 先完成一条可演示的纵向切片，再建设横向模块。
3. 外部依赖只在真实 seam 上设 adapter；测试替换 adapter，不在生产保留 mock fallback。
4. 测试夹具只进 `tests/` 或临时数据库，不进入用户大脑文件。

## M8：真实模型主链可信化（已完成）

- 主张抽取返回明确结果：成功、没有可核对主张、未配置模型、模型输出不合格、调用失败。
- 结构化响应解析兼容纯 JSON 与常见代码围栏；Zod 校验失败保留安全、可展示的原因。
- IPC 必须捕获模型/网络错误，抽取作业一定结束，不得永久卡在“抽取中”。
- 结果卡不得把“模型失败”写成“未配置模型”。
- 资格认证复用同一抽取 interface；技术失败不得显示“已认证”。
- 用用户已配置的真实端点在临时大脑文件中跑一遍：材料 → 绑定 → 抽取 → 投影 → 简报；临时数据结束即销毁。

验收：全量测试、构建、E2E 通过；真实端点至少连通/能力通过，抽取失败时能给出准确原因；用户业务库不增加隔离样本。

## M9：真实进料

- 新建进料 module，统一处理粘贴文本、URL、文本文件与 PDF；渲染层只选择/展示，读取与网络获取在主进程。
- 手给 URL 成功拿到正文后才写来源；失败只记录获取失败，不把 URL 字符串伪装成正文。
- PDF 本地解析，保留文件名、页码与可定位片段；设置大小、页数、超时和 MIME 限制。
- 来源记录补充原始定位元数据，升级 schema 时保留向后迁移。

验收：真实 URL、TXT、PDF 各走一遍入库与抽取；任何失败都不产生假正文或假主张。

## M10：记忆与调研补全

- 实现 ADR 0022 尚缺的会话候选记忆抽取和独立整理循环；明确“记下来”仍即时写，闲聊不产候选。
- 把 Agent Reach 体检、搜索、打开收进一个深 module；真实安装不可用时给安装/降级说明，不保留假搜索结果。
- 完成周期性雷达的创建、计划与补跑入口，而不只保留启动时 catch-up。

验收：候选记忆可追溯到会话并经人确认；真实调研回放含查询、打开、失败 URL 和停止原因。

## M11：质量回归

- 把产品评测从单次分数卡扩成可重复的主链回归：抽取召回、span 命中、FTS Recall@k/MRR、简报忠实、未知遵守、冲突检出、纠正复发。
- 认证结果按“端点 + 模型 + 配置指纹”持久化；配置改变立即失效。
- 建立真实测试数据清单与清理规则；金标仍只在隔离库运行。

验收：一次命令和设置页都能运行同一组评测，并能定位失败发生在获取、抽取、召回还是出站。

## M12：发布可靠性

- 启动前备份、迁移失败恢复、导入/导出校验、数据库完整性检查。
- 安装包版本、应用图标、代码签名与升级策略；CI 上传可追踪产物。
- 本地诊断包只包含脱敏日志和 schema/版本信息，不含密钥与材料正文。

验收：全新安装、覆盖安装、损坏配置恢复和数据库迁移均有自动化冒烟。

## 暂不做

- 云同步、多租户、运营账号、Redis/Postgres。
- 同时铺开多种 LLM 协议；先把 OpenAI-compatible Chat Completions 主链做稳。
- 向量库或知识图谱展示；先用评测证明 FTS 不够，再新增真实 seam。
- 模型自动写账本；所有写入仍遵守 ADR 0028 的提议与人工确认。
