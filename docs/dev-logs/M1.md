# M1 验收说明

状态：实现会话自测完成，停下等用户亲手走查。不开始 M2。

## 做了什么

- 新建 `app/`：electron-vite 三层（main / preload / renderer）+ React 19 + TypeScript strict。
- 主进程 `better-sqlite3` 打开大脑文件；空库走迁移，写出 `schema_migrations`、账本表和 `claims_fts`。
- 首启只预置场景预设包：四个内置场景加「自定义」的槽表（`slot_defs`）和简报说明（`scenario_brief_specs`），数据来自 `prototype/src/scenario.ts` 的 `DEFAULT_SLOT_DEFS` / `BRIEF_SPECS`。库里没有栈桥科技 / 周若水 / NordStream / LuftData。
- 账本规则在主进程：冲突派生（0029）、纠正未核=丢弃不写禁写、纠正已晋升=关窗+禁写、晋升只翻未核、闲聊不写主张、绑定须确认、未绑定不投影。抽取是绑定后的桩，不是 0024 真循环。
- 原型壳迁到渲染层，store 改为 IPC 桥。界面中文，功能名不出现 Graphiti / Mem0 / dream / LightRAG。
- 根脚本：`npm run dev / build / lint / typecheck / test / e2e`。单测用 Electron 运行时加载 native 模块，与窗口 ABI 一致。

## 用户怎么点

1. 仓库根：`npm install`；`cd app && npm install && npm run rebuild`（打 better-sqlite3 的 Electron ABI）。
2. `npm run dev`（根或 app）。首次打开是空工作区 / Inbox，不是无对象的对话首页。
3. 左栏新建工作区（选场景）→ 新建对象 → 主栏对话，右栏档案槽为空（未知）。
4. Inbox 粘贴文本 → 选对象 → 点确认绑定。未点确认不会抽出主张。
5. 绑定后出现抽取中，随后未核主张上页。普通闲聊主张条数不变。
6. 关掉应用再打开，刚才的工作区、对象、来源、主张、会话还在。

## 自测证据

- vitest 16 项两次全绿，brain 层行覆盖 88%（门槛 80%）。
- 真实入口启动两次：主进程 `better-sqlite3 loaded`，大脑文件被创建，渲染进程起来。经 IPC `dispatch` 写入一区一对象后完全退出再启动，对象仍在且可见。
- `npm run lint` / `npm run typecheck` 绿。渲染层被 ESLint 禁止 import main。

## 已知问题

- 设置里的三级自检仍是原型模拟，不真连模型（M2）。
- 主张抽取是桩（按句切、关键词对槽），不是 0024 结构化循环（M3）。
- 开发态 preload 产物是 `index.mjs`，主进程按文件是否存在选择 js/mjs。
- 单测必须走 `ELECTRON_RUN_AS_NODE`（`npm test` 已封装）；纯 Node 加载会因 ABI 对不上而失败。
- 未做安装包、托盘、首启向导、密钥进钥匙串（M7）。

## 偏离计划

- `better-sqlite3` 用 12.9 而不是 11：本机 Node 24 没有 v11 预编译，v12 才有 Windows x64 预编译。
- 预设简报说明落在 `scenario_brief_specs`，序号落在 `app_meta`：§3 未单列这两张表，否则首启无法把简报说明和序号写入大脑文件。
- M0 工具链并进本批，不单独停下来做 M0 验收。
