# StaffDesk 产品终态路线图（2026-09-03 制定）

本文件是后续所有刀的总施工依据，收敛三类输入：实机用户路径走查（docs/manual-ux-test-2026-09-03.md）、五轮审计残余、里程碑记账遗留。每刀 intake 时以本文件为准取样；本文件由 Owner 维护，裁决变化先改这里再开工。

## 一、最终产品形态目标（终态定义）

**StaffDesk 的终态不是更多功能，而是现有功能面达到产品级质量。** 功能边界以 CONTEXT.md 词条全集为准（M30 已宣称功能面齐平），向量召回 / 登录态平台 / 费用折金额等已裁决出范围（0042/0060/0061/0059），本路线图不重开。

终态验收六维（全部机械可断言或可复走）：

| 维度 | 含义 | 验收口径 |
|---|---|---|
| 装得上 | 安装包持久可获取，装机链路自动验证 | tag → 三 job → 装机终验 → 自动 Release 全链绿；README 下载链接有效 |
| 起得来 | 崩溃与损坏有防线 | 损坏库旁置+引导；强杀重开账本一致；兜底 handler 落日志（已有，回归守护） |
| 用得顺 | 用户路径无假信号、无内部泄漏、无死入口 | §三 阶段一二清单全清 + 真机复走全路径零 P1/P2 |
| 信得过 | 账本纪律在真实路径上成立（不止于单测） | 未验证闭环清单（§二.3）全部经真机走查；提议/晋升/丢弃无矛盾态 |
| 讲得出 | 仓库门面撑得起简历叙事 | README+截图+ADR 索引+质量 badge+Release 页完整 |
| 养得起 | 维护态可持续 | dependabot 分诊节律；版本策略执行；审计节律延续 |

### 3. 台账处置原则

- 每项必须落位到某刀或明确挂「观察」；修完逐项回填来源文档 ID（走查项回填 manual-ux-test，审计项回填下轮审计核对）。
- 域难设计（滞留阈值、0027 裁决）先 ADR 后代码（0064 起）。
- 账本规则修复纯函数测试先行；UI 修复补组件/e2e 测试；交付前真实 Electron 窗口复走原路径。

## 三、分阶段计划（刀位映射）

### 阶段〇：收尾杂项（随下刀带走，不占刀位）

tag 重推（#46 合并后）→ description/topics → dependabot 分诊（合分组内小版本，关跳大版红 PR，留 typescript 7 / vite 8 等待专项评估）。

### 阶段一 M38「正确性收口刀」——用得顺 + 信得过的硬缺口

优先级最高的 P1 与数据正确性，全部带自动化测试与真机复走：

1. **UX-001**（ADR 0064 已落）：滞留按主张入库满 N 天（默认 7，设置 1–90，跟机器走）；晋升/纠正/关窗/删除刷新丢弃卡；接受按 live 重算并展示实作清单；打开待确认扫描；驳回后集合不变不再出卡。
2. **UX-002**：正文剥离 `[ref:]`（合法/非法/重复/贴标点四态单测），引用只走引用卡。
3. **UX-003**：未编目降级幂等化（buildBrief/一次净化/重复净化三路输出一致），复制与导出同口径。
4. **UX-004**：简报任务落审计步骤（开始/组装/出站校验/完成），失败任务可见失败阶段。
5. **UX-006**：时间语义统一（持久层 UTC 或带时区，展示层转本地；UTC/UTC+8/跨日三态测试；排序按真实时间）。
6. **UX-009**：批量卡计数口径拆分（「还有 N 个待确认操作」vs「本操作含 M 条主张」）。
7. **UX-007**（维持 0027）：对象页来源解绑 / 删除 / 重试抽取改为右栏入口 + 主栏确认卡，与设角色同一条路；Inbox 绑定例外不变。不新开 ADR，0027 已补执行说明。
8. **双生成怪癖**（台账 C）：简报 DONE 幂等或效应去重，一次生成一份。

验收：走查报告 §5 全部门禁 + UX-001~004/006/009/007 的自动化测试 + 真机复走原路径零 P1。

### 阶段四 M40 审计刀（第六轮）+ 终态验收 → v1.0.0

- 未验证闭环清单（§二.2.E）在此轮走查线全覆盖（纠正禁写/候选记忆/调研/雷达/删除恢复）。
- 终态验收 = §一 六维全绿 → 打 **v1.0.0**（首个宣称「完整产品」的版本）。

### 维护态（v1.0.0 后）

1. **用户路径走查**进入刀规：UI 密集刀的必过门（真机复走），审计刀固定环节——本次实机一次抓出 4 个 P1 而五轮代码审计为零，教训入档。
