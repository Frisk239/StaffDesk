# 产品原型计划

纯前端、可点、假数据。用来验证用户能不能按已锁设计办事，不是实现大脑。

**要回答的问题：** 对着一个对象，从丢材料到出简报再到纠正，这条链在界面上是否成立？点下去会不会写出账本不该有的东西？

**不回答：** 真模型、SQLite、Electron 主进程、Agent Reach、抽取循环实现、评测跑分。这些只以状态和徽章出现。

真值仍以 `CONTEXT.md` 和 `docs/adr/` 为准。本文件只规定原型范围、布局、屏幕、状态机和验收。词条冲突时以词汇表为准，不要在原型里发明新领域概念。

视觉（字体、色板、圆角、动效）由执行会话自定。布局和交互不得自定。不要做成 ChatGPT / NotebookLM 对话居中。不要做成落地页。

---

## 放哪、怎么跑

- 代码放仓库根目录 `prototype/`，目录名必须让人看出这是一次性原型，不是成品。
- Vite + React + TypeScript。状态全在内存，刷新即丢。不要接后端、不要 SQLite、不要 Electron。
- 一条命令能开：`prototype/package.json` 里 `dev`，仓库根也可加 `"prototype": "npm run dev --prefix prototype"`。
- 界面中文。
- 浏览器打开后必须能走完下面「主链」。不要只做静画。

---

## 范围

做：

1. 桌面壳（假窗口即可）+ 左侧栏 + 对象页三栏
2. Inbox：未绑定来源，绑定须人确认
3. 对象页：档案投影、来源、对话
4. 主张抽屉
5. 出简报（面试一页纸）
6. 纠正（关窗 + 关闭原因 + 禁写）
7. 晋升（按条）
8. 待确认：整理提议和候选记忆两段，一个列表
9. 抽取中 / 未核 / 冲突 / 未知 / 过时 / 未编目 / 禁写 这些状态可见

不做：

- 真检索、真打开 URL、真 PDF 解析
- dream 页面或菜单（内部名，不进界面）
- 调研任务真跑、雷达、回放逐步工具调用
- 设置里的 BYOK / 模型（可留灰按钮，点了提示「成品才有」）
- 评测仪表盘
- 对象别名 / 同一性
- 登录

调研、出简报、任务回放三个顶栏动作：出简报可走通；调研和回放可点，用假进度或空态说明「成品才跑」，不要做假搜索结果灌进账本。

## 布局（锁死）

对齐 ADR 0011 / 0015。结构变体不做。执行会话只在这个骨架里决定视觉。

```
┌─────────────────────────────────────────────────────────────┐
│  假桌面标题栏（StaffDesk · 当前对象名）                        │
├────────┬────────────────────────────────────────────────────┤
│        │  顶栏：调研 · 出简报 · 任务回放     当前对象名        │
│ 左侧栏  ├──────────────┬──────────────────┬─────────────────┤
│        │              │                  │                 │
│ Inbox  │  档案投影     │  已绑定来源      │  对话            │
│ 人     │  （正中）     │  （一侧）        │  （另一侧或底部） │
│ 组织   │              │                  │                 │
│ 项目   │              │                  │                 │
│ 待确认 │              │                  │                 │
└────────┴──────────────┴──────────────────┴─────────────────┘
```

### 左侧栏

原型默认（尚未升成产品 ADR，原型必须按此做，点完再决定是否写入词汇表）：

- Inbox
- 人
- 组织
- 项目
- 待确认（角标 = 未处理条数）

点某一对象 → 右侧换成该对象页。Inbox / 待确认不是对象页。

没有全局聊天入口。没有「新对话」当首页。

### 对象页

- **正中：档案投影。** 主张按谓词槽分组（任职于、在招岗位、使用技术、办公地点、融资轮次；未编目单独一段）。冲突双方并排，不合成「目前有争议」。未知格子空着并标明未知，不准用散文填满。未核有标记。过时默认不进当前投影，抽屉里仍能看到。
- **一侧：已绑定来源。** 标题、进料路径（手给/调研）、主键/转述若已标、绑定对象。未绑定的不出现在这里。
- **另一侧或底部：对话。** 默认只问、带引用。写入只有明确「这句不对 / 记下来」。
- **顶栏：** 调研、出简报、任务回放，都挂在当前对象上。

主张账本不是主表。点投影里的一句才打开抽屉。

### Inbox

未绑定列表。每条能打开原文（假文本）。上页必须走绑定：挑至少一个对象，人点确认。可同时挂多个对象。不自动乱绑。绑定成功后该来源从 Inbox 主列消失（或标已绑定），对象页来源侧出现，并触发「抽取中」。

### 待确认

一个页面，两段，不要两套界面：

1. **整理提议**（动账本，须人确认）：合并重复、标可能过时、未编目谓词编目
2. **候选记忆**（不自动升）：会话扫出的偏好

每条：接受 / 驳回。接受才改内存里的账本或记忆。

## 主链（必须可点通）

种子数据启动后，用户不靠改代码就能做完：

1. 打开 Inbox，看到一份未绑定的官方 JD（手给，文本）。
2. 绑定到组织「栈桥科技」（可同时挂项目「后端实习 2026 秋招」）。须点确认。
3. 对象页来源侧出现该 JD。投影先进入「抽取中」，约 1 秒后出现未核主张（内存直接写入，假装主张抽取循环）。
4. 投影按槽分组。至少有：在招岗位一条、使用技术两条互斥冲突并排、办公地点未知空着、未编目一条（不画冲突、不当定论）。
5. 点开一句，抽屉含：正文、状态、关闭原因（若有）、冲突双方、原文片段、进料路径、是否未核、谓词槽或未编目。
6. 顶栏「出简报」→ 面试简报。块：组织是谁、在招什么、技术信号、可能问什么、材料缺口。无出处的句子不准出现。未核必须带标记。冲突摊开双方。未知占位。缺口里写清办公地点未知。
7. 在抽屉或对话里纠正一条错误技术主张：关窗、必填关闭原因（世界已变 / 从未成立）、可选新主张（使用者陈述）、写入禁写。投影当前句改掉；旧句留在抽屉。再出一份简报，被禁写的错句不得再当单边定论。
8. 按条晋升一条未核；简报里该条不再带未核（若已晋升）。

对话补充：输入普通问题 → 只解释并引用已有主张，不写账本。输入「记下来：简报用条目」→ 立刻一条全局记忆（或进候选，二选一：明确「记下来」走立刻写）。输入「这句不对」且选中某主张 → 走纠正，不走闲聊抽取。

## 种子数据

不要用 Acme / John Doe。用下面这套，可改文案不可改结构。

**对象**

| 种类 | 名称 |
|---|---|
| 组织 | 栈桥科技 |
| 项目 | 后端实习 2026 秋招（属于栈桥科技） |
| 人 | 周若水（面试官，可挂关系到组织，页上能跳） |

**来源**

- Inbox 起始：`jd-zhanqiao.txt`，手给，未绑定。正文里明确写：招聘后端实习、主栈 Go、工作地点未写。另有一句含糊「也在看 Java 方向」给冲突用。
- 绑定后可再内置一条已绑定的官网摘录（手给或调研未核），主张「主栈是 Go」。与 JD 里「也在看 Java」冲突。

**主张（绑定抽取后写入，默认未核）**

- 槽 `在招岗位`：栈桥科技 2026 秋招在招后端实习。（JD 片段）
- 槽 `使用技术`：栈桥科技后端主栈是 Go。（官网片段）
- 槽 `使用技术`：栈桥科技后端也在招 Java。（JD 含糊句）→ 与上一条冲突，并排
- 槽 `办公地点`：无材料 → 投影该格为未知，不编
- 未编目：从 JD 抽出「团队正在搞内部平台化」→ 可见、未核、不进冲突、简报不当单边定论

**记忆**

- 无，或一条全局：「简报用条目，别写长」（可在演示里用「记下来」现场写）

**整理提议（待确认里预置一条）**

- 未编目「平台化」建议丢掉或并入某槽，等人点

不要在种子里放世界事实进记忆。

## 内存状态（执行会话按此建模，不必做成库）

最小字段，名字跟词汇表走：

- `objects[]`：id, kind(人|组织|项目), name, relationIds
- `sources[]`：id, title, body, path(手给|调研), boundObjectIds[], primary? 
- `claims[]`：id, objectId, predicate(槽名|未编目), text, status(成立|部分成立|过时|未知), unverified, validFrom?, validTo?, closeReason?(世界已变|从未成立), sourceId, span, supersededBy?
- `conflicts[]`：claimIdA, claimIdB（同一 objectId + 同一受控谓词 + 有效期重叠 + 取值互斥）
- `briefs[]`：id, objectId, taskId, createdAt, blocks[]（每块句子带 claimIds 和 unverified）
- `memories[]`：id, scope(全局|对象|会话), text, kind(偏好|禁写|习惯)
- `inbox`：未绑定 source ids
- `extractJobs[]`：sourceId, status(抽取中|完成)
- `proposals[]`：type(整理|候选记忆), payload, pending

规则（必须写进 reducer，不要只画在 UI 上）：

- 未绑定来源不投影、不进对象对话默认语境
- 绑定须人确认；确认后才入队抽取
- 闲聊不 `push` claim
- 「记下来」立刻写 memory；纠正立刻关窗 + 禁写
- 未编目不创建 conflict
- 简报只读当时能出站的主张；无 claimId 的句子不准生成
- 禁写命中的措辞，简报不得再当单边定论
- 未知格子保持空，禁止用模型常识假句子（原型里就是禁止手写填白）

对话可用脚本回复：按用户问题从当前对象 claims 挑引用。不要现场编新主张。

## 屏幕清单

| 屏 | 有什么 | 没有什么 |
|---|---|---|
| 空大脑 | 左侧栏空、Inbox 引导丢材料 | 居中大聊天 |
| Inbox | 未绑定列表、打开原文、绑定对话框 | 自动归类完成态 |
| 对象页 | 三栏 + 顶栏 | 主张主表、compiled truth 简介 |
| 主张抽屉 | 审计字段 | 置信度分数 |
| 简报 | 面试五块 + 引用 + 未核 + 缺口 | 无出处段落 |
| 待确认 | 两段列表 | dream、两套审核后台 |
| 对话 | 引用气泡、「这句不对」「记下来」入口 | 自动抽主张的 loading |

空态、抽取中、绑定确认、纠正填原因，都要能看见。不要只有成功态。

## 验收

执行者做完后自己点一遍，再交给主人。全过才算原型刀完成：

1. 启动后不是对话首页
2. 未绑定 JD 不出现在任何对象投影里
3. 不点确认无法绑定
4. 绑定后出现抽取中，随后未核主张上页
5. 冲突并排，没有「目前有争议」合成句
6. 办公地点是未知空格，不是「暂无数据请补充」式编造
7. 未编目可见，简报不当单边定论
8. 抽屉能看到原文片段和进料路径
9. 简报五块齐全；每句能点回主张
10. 纠正后旧句仍在抽屉；新简报不再单边用被禁写的错句
11. 闲聊之后主张条数不变
12. 待确认接受/驳回会改状态
13. 界面中文；无 Graphiti / Mem0 / dream / LightRAG 当功能名
14. 刷新丢失状态（证明没有偷偷做后端）

## 执行时不要做

- 不要改 `CONTEXT.md` / `docs/adr/`，除非点着发现和词条真打架，先停下来问主人
- 不要把 `reference/` 做成功能
- 不要为了好看把对话拉到正中
- 不要做三种布局变体（布局已锁）
- 不要引入路由库之外的状态持久化
- 不要开始实现正式应用的 `src/` 骨架；成品代码不在这一刀
