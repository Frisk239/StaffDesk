# 不可补偿清单：永久删除对象与移除工作区；日常动作全额可补偿，删除来源可补偿但不做一键

撤销的便利和二次确认的分量是互补的，不该叠加在同一批动作上：天天做的动作要宽容（随手可撤），重型动作要严肃（确认即终局），否则确认弹窗失去威慑、撤销稀释决策。StaffDesk 账本写动作分三档：全额可补偿——晋升（含批量）、整理并入/丢弃、绑定、解绑、写记忆/接受候选、纠正关窗（补偿=重开，须填原因），结果卡上直接给撤销；可补偿但不做一键——删除来源，补偿得出来（正文在日志里，重放绑定+重开其主张），但它已有「列出受影响主张数+二次确认」的闸门（0031），想恢复走设置页显式回退，不叠一键；不可补偿——永久删除对象、移除工作区（0032 的两级重型动作），保留其威慑性即设计本身，且移除工作区真正失去的只有名字与场景配置，补偿价值趋近于零。本清单是 0028「不可逆或越界不给模型工具」在账本侧的镜像：改密钥、开深挖档不属于账本写动作、不进操作日志，不在本清单讨论。补记：撤销不设时间窗——补偿写是正常写操作而非特权操作，不用特权方式（时限）约束；单条日常动作的结果卡常驻一键撤销（hover 呈现，不做视觉噪音），批量晋升的补偿走 takeover 确认。防误撤靠确认闸，不靠时间；显式回退（设置页、审计卡）永远可用。
