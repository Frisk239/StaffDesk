# M21 — quality knife: eval floors, orchestration unification, redaction consolidation

## Scope

质量刀三件事：eval 金标升级（低分失败路径、未编目纪律、撤销补偿三个新面）、调研编排两份漂移副本合一（catchup 补单飞锁、修掉未脱敏 TOAST 泄密口）、脱敏 helper 十一份收口为统一工具。红线：不新增账本功能面；UI 只补两个指标标签。

## Changes

- **eval 门槛（低分失败路径）**：`QUALITY_METRIC_FLOORS` 落在 fingerprint.ts（0045 的「政策」面）：抽取召回 70 / 出处命中 60 / Recall@k 与 Precision@k 60 / MRR 0.5 / 简报忠实 90 / 未知遵守 90 / 冲突检出 80 / 纠正复发 90 / 未编目纪律 90 / 撤销补偿 90 / 编造率上限 10。runner 每 stage 收尾比对门槛，未达即标失败并在 detail 点名指标与差距——指标低分从此会真的失败，不再只有异常才失败。
- **新指标 uncatDiscipline**：金标包加 uncatCases（gold-tech 正文新增映射不上的句子，expected 带 `predicate:'未编目'`）；断言引用未编目主张的简报句必须带降级 flag，不作单边定论（0037）。validator 加锚定校验防止空 cases 假合规。
- **新指标 undoCompensation**：金标包加 undoCases；runner 纯 dispatch 剧本（ENQUEUE_WRITE 晋升 → CONFIRM_WRITE → 结果卡带 undo 载荷 → UNDO_RESULT），断言主张回未核、operations 恰有一行 `undo_of='compensating'`、撤销后简报句带未核标记（0034）。
- **deterministic adapter 加 sabotage 模式**（丢一半主张 + 失效 span + 注入伪主张），测试据此证明低分路径：三 stage 失败、detail 点名指标与「低于下限」。
- **政策版本**：`QUALITY_POLICY_VERSIONS.outbound` 升 `ledger-outbound-v2`（出站规则新增两条，按 0045 换版本即回落未认证，设计内行为）。设置页资格卡补「未编目纪律 / 撤销补偿」两个标签。
- **编排合一**：新建 `tasks/applyResearchRun.ts` 统一编排（模块级单飞锁 + checkpoint 存活检查 + executeExtractionJob 可注入缺省自建，不 import electron）；ipc 的 `runResearchAndApply` 变薄壳，index 删掉约 60 行漂移副本 `runDueRadarCatchup`。锁语义有意收紧：启动补跑与手动调研撞同一对象时补跑侧跳过并 TOAST。
- **脱敏收口**：新建 `src/main/redact.ts`（maskSecret / maskTruncated / safeDetail），11 处内联副本与 chatCompletions 导出版全部迁移，逐站点保留现行截断长度；persist 的 redactSecrets 因是结构性整字段清空保留原位。修复两处泄漏面：catchup 失败 TOAST 原为未脱敏 `slice(0,120)`；chatCompletions 原「首尾露出」切片行为废除（连内容轮廓都不留）。
- **广播合一**：`windowBroadcast.ts` 成为 'state:changed' 唯一出口，ipc/index 两份同实现删除。
- **任务停止用例不进金标**（范围裁决）：engine 停止语义已由 tests/tasks/engine.test.ts 钉住，eval 造 reach 剧本不产生新信号，留待真实调研回归需要时再议。
