# 质量回归只用一套 runner；资格记录属于产品全局配置

ADR 0010 已确定评测是产品能力，0039 已确定设置自检分为连通、能力探测、资格认证，
0043 又把模型配置提升到了产品全局。但现有实现把命令行回归和设置页资格认证分成两条路径，
认证结果还只挂供应商 ID，既不能证明实际跑的是哪一个模型，也会随大脑文件切换而丢失。

StaffDesk 只维护一套质量回归 runner。runner 的公开 interface 接收金标包和 completion adapter，
依次穿过获取、抽取、召回、出站四阶段，返回结构化报告；命令行使用确定性 adapter，设置页使用
当前 BYOK 模型 adapter，除此之外金标、指标和生产规则完全相同。获取复用文本进料 seam，抽取复用
主张抽取循环，召回复用 FTS 与命中对账，出站复用简报、冲突与纠正规则，不复制一套“评测版”业务规则。

每个金标包在独立的 `staffdesk-eval-*` 临时目录和 SQLite 大脑中运行，成功、失败都在 finally
关闭并清理；任何评测数据都不得进入使用者大脑文件。内置金标只含虚构对象与材料；报告只保留包 ID、
阶段状态、安全短原因和聚合指标，不保留金标正文、模型请求、API Key 或请求头。

资格认证记录存入 Electron `userData` 下独立的安全 JSON 文件，属于产品全局状态，不写入 brain.db。
记录按配置指纹寻址，可保留旧历史；只有当前指纹的成功记录能认证当前配置，因此切换大脑不丢，
配置变更也不会错误继承旧认证。运行开始时冻结 target；运行途中若设置改变，结果仍只写回旧 target
的指纹，不能贴到新配置。

配置指纹由以下规范化字段组成：去首尾空白、去末尾斜杠并规范协议/主机大小写及默认端口的 endpoint，
模型 ID，思考强度，有效模型参数（当前为上下文窗口与最大输出），评测集版本，以及抽取、召回、出站
策略版本。对象键稳定排序后做 SHA-256。API Key、供应商 ID 和供应商显示名称明确排除：换密钥不改变
模型能力身份，重命名或重建同一端点也不应让资格失效；反之，上述任一有效字段或策略版本变化都立即
产生新指纹并显示未认证。

设置页与 IPC 必须显式传 `providerId + modelId`。不得在模型行点击后暗中测试 active 模型或首个模型。
连通、能力探测、资格认证的三级结构保留；未认证仍可使用，编造率超过 5% 仍按 0039 强警告而非硬闸。
不引入第二套长期 LLM 配置，不做模型排行榜、历史趋势、向量库或模型裁判。
