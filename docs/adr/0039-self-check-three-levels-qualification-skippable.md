# 设置自检分三级：连通、能力探测、资格认证；首启认证必跑可跳过，未认证徽章持续可见

BYOK 的结构性事实：SaaS 厂商在 CI 里评测，因为模型是它的常量；StaffDesk 出厂时模型未定，模型是用户变量，所以评测只能发生在用户机上、用用户的 key（0010「评测是产品能力」的最强理由）。原型的「测试连接不真连」升级为三级自检：连通（秒级免费：密钥格式、端点可达）、能力探测（几厘钱：带结构化输出的微型请求，回答这个模型能不能跑主链）、资格认证（分钟级、目标 ≤$0.10：跑当前工作区场景的内置虚构金标包（0033 三包：面试/求学/选型），出分数卡）。首启向导配置端点后默认进入认证、允许跳过——硬闸会把首启变成挫败源头（临时 key、余额不足、网络问题都常见），但跳过后设置页顶部配置徽章持续「未认证」灰态，换模型或端点后徽章自动回落未认证直到补跑；认证分数卡常驻设置页顶部（已认证绿徽 + 各指标分数）。未认证不是不能用，是「你自己知道这台参谋台没验过」的诚实提示。补记：分数卡的红线只设一条——编造率（负例金标被写成主张的比例），默认阈值 5%、设置可调，触发时强警告但不阻断；其余指标只展示不设闸。分界在能力与纪律：Recall 低、忠实度中游是能力问题，人核与按条晋升弥补得了；编造是纪律问题，负例根本不该存在（来源没说的推论不准写入是第一军规），超标意味着该配置会系统性绕过账本纪律。编造率判定是确定性的——负例主张有标准答案，子串/语义比对即可，不用另一个模型当裁判，避免用模型评模型的循环。
